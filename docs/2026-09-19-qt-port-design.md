# WheelScript 3.0: интерфейс на Qt (PySide6) вместо Tkinter

Дата: 2026-09-19. Предыдущая версия 2.2.1 (Tkinter).

## Зачем

Tk на Windows медленно перерисовывает окно при ресайзе (каждый виджет — отдельное системное окно без двойной буферизации). Тёмная тема в Tk держалась на перекраске каждого виджета и на самодельных выпадающих меню. В Qt тема, меню и заголовок окна красятся сами.

## Что не меняется

`engine`, `model`, `service`, `capture`, `sendinput`, `gamepad`, `rumble`, `storage`, `labels`, `presets`, `shortcut`, `keys` (кроме функции разбора нажатия). Формат `config.json`, профили, portable-режим (`portable.ini`), один экземпляр программы.

## Модули интерфейса

| Файл | Что делает |
|---|---|
| `qt/fields.py` | `Choice` — QComboBox «подпись ↔ ключ». `InputField` — клик, затем кнопка/ось/крестовина руля попадает в поле (опрос 15 мс, таймаут 15 с, Esc — отмена). `KeyField` — клик, затем клавиша или сочетание (собираются, пока хоть одна клавиша нажата), плюс выбор из списка, плюс «✕» для пустого значения. |
| `qt/monitor.py` | `Monitor`: список устройств и живой вид осей, кнопок, крестовин, рисуется QPainter. Перерисовывается только при изменении состояния или ширины. |
| `qt/bindings_model.py` | `BindingsModel` (QAbstractTableModel): колонки Вкл, Название, Ввод с руля, Действие, Параметры. Роль подсветки «срабатывает сейчас». |
| `qt/binding_dialog.py` | `BindingDialog` (QDialog, модальный): название, ввод, режим оси/крестовины, действие, параметры действия, тонкая настройка (мёртвая зона, кривая, порог, инверсия, включена), полоска проверки. Пока открыт — `service.suspend()`, при любом закрытии ровно один `resume()`. |
| `qt/main_window.py` | `MainWindow`: статус (точка + текст), кнопка вкл/выкл, горячая клавиша, профиль и меню «Действия с профилем ▾», таблица привязок и кнопки «＋ Добавить ▾» (пресеты), Изменить, Копия, Удалить, ▲, ▼, монитор справа (QSplitter), нижние настройки (включать при запуске, частота опроса, тема, ярлык, папка настроек), строка геймпада и вибрации. Опрос сервиса QTimer 40 мс. |
| `theme.py` | `LABELS`, палитры `LIGHT`/`DARK` смысловых цветов (все hex), `P` — текущая, `apply(app, mode)` ставит `QStyleHints.setColorScheme` и выбирает палитру по фактической теме Qt. |
| `app.py` | логирование, один экземпляр (сообщение через QMessageBox), `QApplication` со стилем windows11, шрифт, русские тексты Qt, иконка. |

`gui.py` удаляется.

## Клавиши

`keys.from_native(vk, scan, extended)` вместо `keys.from_tk`. Qt на Windows даёт `nativeVirtualKey()` (для Shift/Ctrl/Alt — общий код 0x10/0x11/0x12) и `nativeScanCode()`. Правые модификаторы: Shift по скан-коду 0x36, Ctrl и Alt по флагу extended (бит 24 lParam; Qt кладёт его в `nativeModifiers()` как 0x01000000, его читает `keys.is_extended`). PrintScreen приходит только отпусканием — сохраняем как в 2.x.

## Поведение (как в 2.2.1)

- Щелчок по колонке «Вкл» переключает привязку; второй быстрый щелчок (двойной) переключает ещё раз.
- Повторный щелчок по выделенной строке или щелчок по пустому месту снимает выделение. Двойной щелчок по строке открывает редактор, даже если первый щелчок снял выделение. Delete — удалить (с вопросом), Enter — изменить.
- Строки выключенных привязок серые, срабатывающие подсвечены голубым.
- Все изменения сразу сохраняются в `config.json` и передаются сервису.
- «Как в системе» — Qt сам следует за Windows.

## Сборка

`.venv` в проекте, `requirements.txt` + PySide6-Essentials, `requirements-dev.txt` + pytest-qt. `build.ps1` создаёт `.venv`, гоняет тесты, собирает `--onedir` (как раньше) с исключением tkinter и ненужных модулей Qt, убирает `opengl32sw.dll` и чужие переводы Qt, делает portable zip и setup. Версия 3.0.0.

## Тесты

- Все тесты движка остаются.
- `test_theme.py`: контраст смысловых цветов теперь проверяется и для светлой палитры (она целиком в hex).
- `test_keys_native.py`: разбор нажатий Qt, включая правые модификаторы, для всей таблицы клавиш.
- GUI (pytest-qt, поддельный сервис, окна с `WA_DontShowOnScreen`, реальные диалоги запрещены): сценарии из `test_gui_smoke.py` + инварианты:
  1. Строки таблицы совпадают с привязками активного профиля (текст, «Вкл», серость).
  2. После каждого изменения `config.json` на диске равен `cfg` окна, а сервис получил активный профиль.
  3. `suspend`/`resume` сервиса всегда парные: после закрытия диалога (OK, Отмена, Esc, крестик) и после захвата клавиши счётчик пауз возвращается к исходному.
  4. Отмена диалога не меняет профиль.
  5. Захват руля и клавиатуры заканчивается по вводу, Esc или таймауту; поле возвращается к обычному виду.
  6. Выделение указывает на существующую строку или его нет.
- Случайные последовательности действий в главном окне, мутационная проверка, живая проверка через computer use.

## Что уточнилось при реализации

- **Выделение строки таблицы** рисует свой делегат: стиль windows11 рисует его едва заметной полоской в каждой ячейке, а в тёмной теме оно сливалось с голубой подсветкой срабатывающих привязок. Теперь это заливка цветом акцента и одна полоска слева, заметно отличная и от фона, и от подсветки.
- **Колонки таблицы** делят ширину окна (как в 2.x), горизонтальной прокрутки нет.
- **Esc в редакторе привязки** сначала отменяет захват ввода с руля, второй Esc закрывает окно — где бы ни был фокус.
- **Tab при захвате клавиши** — это клавиша, а не переход к следующему полю; сочетания окна во время захвата не срабатывают.
- **Светлая палитра** теперь целиком в hex (раньше — системные цвета Windows), поэтому контраст проверяется и для неё: 7 тестов, которые раньше пропускались, работают.
- **Установщик** при обновлении удаляет старую папку `_internal` (там были библиотеки Tk от 2.x).

## Результат

- 196 тестов (движок + 46 тестов интерфейса + разбор клавиш Qt), без пропусков.
- Проверка мутациями: 16 поломок ключевых мест интерфейса, все пойманы тестами.
- Сборка: portable 36 МБ, setup 28 МБ. Собранный exe запускается (лог: «3.0.0 starting»). Живая проверка окна — через computer use на демо с поддельным сервисом: тема, монитор, подсветка, редактор привязки.
