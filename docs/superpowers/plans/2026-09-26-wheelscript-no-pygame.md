# WheelScript 3.2.0: ввод без pygame

Дата: 2026-09-26. Предыдущая версия 3.1.0.

## Зачем

pygame в проекте больше не используем. В WheelScript он был только слоем ввода:
опрос рулей и джойстиков (оси, кнопки, хатка), события подключения и отключения, и
заодно он привозил SDL2.dll, через которую `rumble.py` трясёт руль (SDL haptic).
Окно давно на Qt, картинок и звука pygame не делал.

## Что выбрано

**PySDL2 + pysdl2-dll, SDL закреплена на 2.28.4** - той же версии, что привозил pygame 2.6.1.

Почему не прямой XInput/DirectInput через ctypes:

- XInput видит только геймпады Xbox (4 слота, фиксированные оси). Рули, педали и КПП
  подключаются как DirectInput/HID-устройства, XInput их не видит вовсе.
- DirectInput8 через ctypes - это COM-интерфейсы вручную: перечисление, формат данных
  с произвольным числом осей и кнопок, кооперативный уровень, горячее подключение по
  WM_DEVICECHANGE, отдельно haptic (force feedback эффекты). Это сотни строк на месте,
  где сейчас работает проверенный код SDL, и новые места для ошибок на устройствах,
  которых нет под рукой.
- Главное: привязки в `config.json` подписаны GUID устройства в формате SDL
  (`InputSource.device`, `Settings.monitor_device`). Любой другой слой ввода дал бы
  другие ключи, и сохранённые привязки к конкретному рулю перестали бы находиться.

Почему версия SDL закреплена (`pysdl2-dll==2.28.4`), а не последняя: GUID-строки SDL менялись
между версиями (2.26 добавила CRC имени), а нормализация осей, порядок устройств и
причуды haptic у DirectInput (см. регрессию в `tests/test_rumble.py`) - тоже свойства
конкретной сборки. Та же версия - то же поведение для пользователя. Обновлять SDL
можно будет отдельным шагом, с живой проверкой на руле.

Как pygame переводил SDL в Python (повторяем в `Joystick`):

- ось: `SDL_JoystickGetAxis / 32768.0` (0 -> 0.0);
- кнопка: `SDL_JoystickGetButton` (0/1);
- хатка: `(x, y)`, вверх = +1 по y, вправо = +1 по x;
- GUID: `SDL_JoystickGetGUIDString` (32 hex-символа);
- имя: `SDL_JoystickName` в UTF-8.

Что было в `pygame.display.init()` и больше не нужно: подсистема видео. Джойстикам SDL
на Windows хватает своего скрытого окна (DirectInput, RawInput, уведомления о
подключении), события идут через подсистему событий, которую включает `SDL_INIT_JOYSTICK`.
`SDL_JOYSTICK_ALLOW_BACKGROUND_EVENTS=1` ставится как раньше - до инициализации SDL.

Порядок при перестройке списка устройств: сначала `WheelHaptic.attach` (он закрывает
вибромотор отключённого руля), потом закрываются джойстики, которых больше нет, - haptic
не должен пережить свой джойстик. Уже открытые устройства при перестройке не
переоткрываются (как и с pygame: SDL считал ссылки), поэтому вибромотор руля не теряется.

## Шаги (TDD)

1. План - этот файл, коммит.
2. Тесты на новый слой, красные:
   - `tests/fake_sdl.py`: подделка модуля `sdl2` (устройства с осями, кнопками, хатками,
     очередь событий, счётчик открытий и закрытий, haptic как `QuirkySDL`);
   - `tests/test_sdlinput.py`: перевод значений как у pygame, разбор событий
     (подключение, отключение, сдвиг оси), переиспользование открытых устройств,
     закрытие исчезнувших, ошибка открытия, `load()` ставит фоновые события до импорта SDL;
   - `tests/test_service_input.py`: сервис с подделкой SDL - список устройств, ключи GUID
     и `GUID#2` для одинаковых, оси `None` до первого движения, горячее подключение и
     отключение, свой виртуальный геймпад скрыт, вибромотор не переоткрывается при
     перестройке (регрессия JOYDEVICEADDED при старте), закрытие всего при остановке;
   - `tests/test_sdl_real.py`: настоящая SDL из pysdl2-dll с виртуальным джойстиком SDL
     (`SDL_JoystickAttachVirtual`) - без железа, но через настоящую библиотеку;
   - `tests/test_no_pygame.py`: в исходниках, сборке и зависимостях нет pygame;
   - `tests/test_selftest.py`: самопроверка пишет итог, ничего не нажимает;
   - `tests/test_rumble.py`: те же проверки, новые сигнатуры без модуля pygame.
3. Код: `sdlinput.py`, `service.py`, `rumble.py`, `selftest.py`, `app.py`; все тесты зелёные.
4. Мутационная проверка: 3+ поломки нового слоя, каждая ловится тестами.
5. Живая проба: pygame и новый слой в отдельных процессах перечисляют устройства и читают
   оси, кнопки, хатки в покое; плюс одинаковый виртуальный джойстик SDL в обоих - сравнить
   числа, имена, GUID и значения. Без нажатий, мыши, геймпада и вибрации.
   После пробы pygame удаляется из `.venv` проекта, чтобы тесты и сборка шли без него.
6. Версия 3.2.0 (`wheelscript/__init__.py` - единственное место номера), сборка `build.ps1`:
   portable и установщик в `release/`, SDL2.dll в сборке, `--selftest` собранного exe.
7. README EN/RU, CHANGELOG.md, коммиты. Без push и тегов.
