# WheelScript

Превращает игровой руль в мышь и клавиатуру — или в виртуальный геймпад Xbox.
Нужен для игр, которые не понимают руль: поворот руля крутит камеру, педали
жмут клавиши (или курки геймпада), кнопки руля и коробка передач делают что
угодно — клики, сочетания клавиш, прокрутку, кнопки геймпада.

Настройка — в окне программы: кликаешь в поле «Ввод с руля», нажимаешь
кнопку на руле, программа сама её распознаёт.

Проверено на **PXN V9 Gen 2** (с коробкой передач), работает с любым рулём,
джойстиком или геймпадом, который Windows видит как игровое устройство.

## Установка

Готовые файлы собираются в папку `release/` (см. «Сборка»):

| Вариант | Файл | Где хранятся настройки |
|---|---|---|
| Установщик | `WheelScript-<версия>-setup.exe` | `%APPDATA%\WheelScript` |
| Портативная | `WheelScript-<версия>-portable.zip` | `data\` рядом с `WheelScript.exe` |

Портативную версию достаточно распаковать куда угодно (хоть на флешку)
и запустить `WheelScript.exe`. Её отличает только файл `portable.ini`
рядом с exe: если его удалить, программа начнёт хранить настройки в `%APPDATA%`.

Установщик не требует прав администратора (ставит для текущего пользователя),
но при запуске можно выбрать установку для всех. Он создаёт ярлык в меню
«Пуск» (по нему WheelScript находится через поиск Windows) и на рабочем
столе (галочку можно снять). В портативной версии ярлык в «Пуск» делается
кнопкой **Ярлык в «Пуск»** внизу окна; если перенесёшь папку, нажми её ещё раз.

Для режима геймпада дополнительно нужен драйвер **ViGEmBus** — см. раздел
«Режим геймпада». Для мыши и клавиатуры он не нужен.

Запуск из исходников: Python 3.10+. Зависимости ставятся в папку `.venv`
внутри проекта, общий Python не трогается:

```bash
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```

```bash
.venv\Scripts\python run.py
```

## Как пользоваться

1. Подключи руль и запусти WheelScript. Справа, в панели «Что сейчас
   нажато на руле», видно все оси, кнопки и крестовину — удобно проверить,
   что руль виден.
2. Слева — список привязок текущего профиля. Строка подсвечивается голубым,
   когда привязка срабатывает. Клик по колонке «Вкл» временно выключает
   привязку, двойной клик по строке открывает редактор, повторный клик по
   выделенной строке (или по пустому месту) снимает выделение.
3. **＋ Добавить ▾** — выбери шаблон (движение мыши, клавиша, сочетание,
   кнопка мыши, колесо, стик / курок / кнопка геймпада, вкл/выкл…).
   Откроется редактор.
4. В редакторе кликни в поле **«Ввод с руля»** и нажми кнопку / поверни руль /
   нажми педаль / переключи передачу. Поле заполнится само. Esc — отмена.
5. Для клавиши кликни в поле **«Клавиша»** и нажми её на клавиатуре
   (можно сочетание: зажми Ctrl и нажми C). Или выбери из списка справа.
   Работает при любой раскладке.
6. Внизу редактора — **проверка**: покрути руль и увидишь, как привязка
   реагирует, до сохранения.
7. **Включить** (или горячая клавиша, по умолчанию **F8**) — маппинг
   начинает работать. Ещё раз — выключается, все зажатые клавиши отпускаются,
   геймпад возвращается в нейтраль.

Пока открыт редактор привязки, маппинг на паузе — руль не будет «кликать»
по окну настроек.

### Что можно назначить

| Действие | Параметры |
|---|---|
| Клавиша / сочетание | до 4 клавиш; режим: держать, одно нажатие, залипание |
| Кнопка мыши | ЛКМ, ПКМ, СКМ, боковые X1/X2; те же режимы |
| Движение мыши | влево/вправо/вверх/вниз, скорость в пикселях в секунду |
| Колесо мыши | вверх/вниз/влево/вправо, щелчков в секунду |
| Кнопка геймпада | A, B, X, Y, LB, RB, Back, Start, нажатие стиков, Guide, крестовина; те же режимы |
| Стик геймпада | левый/правый, направление влево/вправо/вверх/вниз |
| Курок геймпада | LT / RT, плавно по ходу педали |
| Вкл/выкл маппинг | кнопка руля работает как горячая клавиша |

Режимы нажатия:

- **держать** — клавиша зажата, пока зажата кнопка руля (или педаль за порогом);
- **одно нажатие** — короткое нажатие 50 мс на каждое нажатие кнопки, быстрые
  повторы не теряются (удобно для передач коробки);
- **залипание** — нажал — клавиша зажалась, нажал ещё раз — отпустилась.

### Как читается ось

- **вся ось (−1…+1)** — для руля. С действием «движение мыши» или «стик
  геймпада» поворот влево двигает в одну сторону, вправо — в другую,
  сила зависит от угла.
- **только +** / **только −** — половина оси, например «руль вправо → клавиша D».
- **педаль (покой = −1)** / **педаль (покой = +1)** — отпущенная педаль = 0%,
  в полу = 100%.

Режим подставляется сам при распознавании: педаль определяется по тому, что
в покое она стоит в крайнем положении.

Тонкая настройка: **порог** (с какого нажатия педали срабатывает клавиша),
**мёртвая зона** (сколько руля около центра игнорировать), **кривая**
(больше 1 — точнее около центра, резче у краёв), **инверсия**.

### Режим геймпада

Некоторые игры (особенно гонки и консольные порты) лучше понимают геймпад
Xbox, чем мышь: руль на стике даёт плавное рулевое управление, педали
на курках — плавный газ и тормоз. WheelScript создаёт виртуальный геймпад
Xbox 360, который игра видит как обычный подключённый контроллер.

Для этого нужен бесплатный драйвер **ViGEmBus** — установщик
`ViGEmBus_1.22.0_x64_x86_arm64.exe` со страницы
[github.com/nefarius/ViGEmBus/releases](https://github.com/nefarius/ViGEmBus/releases).
Если драйвер уже стоял, но режим не работает — запусти установщик ещё раз
и выбери **Repair**. После установки перезапусти WheelScript.

Внизу окна показан статус: **Геймпад: не используется** (в профиле нет
геймпад-привязок), **подключён (Xbox 360)** или **недоступен: …** с причиной.
Без драйвера мышь и клавиатура продолжают работать; программа сама пробует
подключить геймпад снова каждые 5 секунд.

Привязки геймпада и мыши/клавиатуры можно смешивать в одном профиле.
Если несколько привязок двигают один стик, их вклад складывается
(и обрезается до края); у курка берётся наибольшее значение.

#### Вибрация из игры

Если игра вибрирует геймпадом (удары, кочки, выстрелы), WheelScript передаёт
эту вибрацию на вибромотор руля. Силу задаёт ползунок **Вибрация из игры на
руль** внизу окна (0% — выключено), кнопка **Проверить** коротко встряхивает
руль. Рядом написано, каким устройством программа вибрирует.

Вибрация идёт, пока маппинг включён и в профиле есть привязки геймпада
(ей нужен тот же драйвер ViGEmBus). При выключении маппинга или открытии
редактора руль сразу затихает. У руля один вибромотор, поэтому два мотора
геймпада смешиваются в один.

Настоящей силовой отдачи (руль тянет в сторону) у PXN V9 Gen 2 нет — в нём
только вибромоторы, так что это максимум, что можно из него получить.

### Профили

Меню **Действия с профилем ▾**: новый пустой, новый стандартный (руль как
мышь), новый «руль как геймпад Xbox», копия, переименовать, удалить,
импорт/экспорт в `.json` — можно держать отдельный профиль под каждую игру
и делиться ими.

### Тема

Внизу окна — **Тема**: как в системе (по умолчанию: переключается вместе
с настройкой Windows прямо на ходу), светлая или тёмная. Окно выглядит как
приложения Windows 11. Тема действует на всё: заголовок окна, меню, редактор
привязки, вопросы и окна выбора файла. На Windows 10 окно выглядит проще,
но работает так же.

### Стандартный профиль (PXN V9 Gen 2): руль как мышь

| Руль | Действие |
|---|---|
| Руль (ось 0) | мышь влево/вправо — поворот камеры |
| Газ (ось 2) | W |
| Тормоз (ось 5) | S |
| Крестовина ↑ / ↓ | мышь вверх / вниз — наклон камеры |
| Кнопка A (0) | ЛКМ |
| Кнопка B (1) | ПКМ |

### Профиль «Руль как геймпад (Xbox)»

| Руль | Геймпад |
|---|---|
| Руль (ось 0) | левый стик влево/вправо |
| Газ (ось 2) | курок RT |
| Тормоз (ось 5) | курок LT |
| Кнопка A (0) / B (1) | A / B |
| Крестовина руля | крестовина геймпада |

Не назначены, но доступны: сцепление (ось 6), передачи 1–6 и R (кнопки 16–22),
остальные кнопки.

## Частые вопросы

**В игре ничего не происходит.** Если игра запущена от администратора,
Windows не даёт обычным программам слать в неё ввод — запусти WheelScript
тоже от администратора.

**Педаль жмёт клавишу, хотя её не трогали.** Проверь в редакторе режим оси
(«педаль (покой = −1)» или «(покой = +1)»). До первого движения SDL отдаёт
у педалей 0 вместо реального значения, поэтому ось с подписью «ещё не
двигалась» программа специально игнорирует — достаточно один раз нажать педаль.

**Камера крутится, когда руль в центре.** Увеличь мёртвую зону.

**«Геймпад: недоступен: не установлен драйвер ViGEmBus».** Установи или
почини драйвер (см. «Режим геймпада»).

**Руль не вибрирует.** Нажми «Проверить» внизу окна. Если руль не дрогнул,
рядом написана причина (например, «у руля нет вибромотора»). Если дрогнул,
а в игре тихо — игра не вибрирует геймпадом или не видит виртуальный
геймпад (проверь статус «Геймпад: …»).

**Игра видит и руль, и геймпад и путается.** Отключи в настройках игры руль
как устройство ввода или выбери в ней контроллер Xbox.

**Курсор на рабочем столе двигается «рывками» или ускоряется.** Это
«повышенная точность указателя» Windows; в играх с raw input её нет.

**Лог и настройки** — кнопка «Папка настроек» внизу окна
(`wheelscript.log`, `config.json`). Если `config.json` испорчен, программа
сохранит его как `config.broken-*.json` и запустится с настройками по умолчанию.
Конфиги от версии 2.0 читаются без изменений.

## Сборка

Нужны Python 3.10+ (64-bit) и [Inno Setup 6](https://jrsoftware.org/isinfo.php)
для установщика (`winget install JRSoftware.InnoSetup`).

```bash
powershell -ExecutionPolicy Bypass -File build.ps1
```

Скрипт сам создаёт `.venv` в папке проекта (если его нет) и ставит туда
зависимости из `requirements-dev.txt`, прогоняет тесты, собирает exe через PyInstaller, пакует
`release/WheelScript-<версия>-portable.zip` и `release/WheelScript-<версия>-setup.exe`.
Если Inno Setup не найден, собирается только portable. Драйвер ViGEmBus
в сборку не входит — он ставится отдельно.

## Тесты

Движок, модель, распознавание ввода, формат SendInput и отчёт геймпада
проверяются property-тестами на [hypothesis](https://hypothesis.readthedocs.io/):
генератор придумывает тысячи случайных профилей, состояний руля и
последовательностей действий и проверяет инварианты, например:

- ни одна клавиша не нажимается дважды и не отпускается без нажатия;
- после выключения, смены профиля или отключения руля ничего не остаётся зажатым,
  а геймпад возвращается в нейтраль;
- выключенный движок не шлёт ни одного события;
- сумма целых сдвигов мыши отличается от точной меньше чем на 1 пиксель;
- руль влево и вправо дают строго противоположное движение;
- стик геймпада в точности повторяет руль, сумма стиков не выходит за край,
  курок равен наибольшей из педалей;
- любое состояние геймпада (даже NaN) влезает в формат отчёта Xbox без переполнения;
- вибрация на руле не прерывается, пока игра её просит, и гаснет, как только
  игра затихла или маппинг выключен;
- текст в обеих темах контрастен фону (по WCAG), а смена темы сразу
  перекрашивает монитор, подсветку и надписи;
- таблица всегда совпадает с активным профилем, а `config.json` на диске —
  с тем, что показано в окне (проверяется после каждого шага случайных
  последовательностей действий);
- маппинг ставится на паузу ровно на время редактора привязки или захвата
  горячей клавиши, как бы окно ни закрыли (Сохранить, Отмена, Esc, крестик);
- захват кнопки руля и клавиши заканчивается вводом, Esc или таймаутом;
- правые Shift, Ctrl и Alt различаются при захвате клавиш;
- каждое «одно нажатие» длится не меньше 50 мс и ни одно не теряется;
- любой JSON, даже мусорный, превращается в валидный конфиг и пишется обратно в UTF-8;
- педаль, «прыгнувшая» из 0 в −1 при первом отчёте, не считается нажатием.

```bash
.venv\Scripts\python -m pytest
```

Долгий прогон (5000 примеров на каждое свойство):

```bash
.venv\Scripts\python -m pytest --hypothesis-profile=thorough
```

## Устройство проекта

```
wheelscript/
  engine.py     чистый движок: состояние руля + dt → события (без WinAPI)
  model.py      профили и привязки, разбор и нормализация JSON
  capture.py    распознавание «нажми кнопку на руле»
  service.py    фоновый поток: pygame, опрос устройств, запуск движка
  sendinput.py  WinAPI SendInput (scan-коды, extended-клавиши, мышь, колесо)
  gamepad.py    виртуальный геймпад Xbox 360 через ViGEmBus (vgamepad)
  rumble.py     вибрация из игры на вибромотор руля (SDL haptic)
  keys.py       таблица клавиш
  presets.py    шаблоны для «＋ Добавить»
  labels.py     подписи действий и вводов
  storage.py    где лежат настройки (portable / %APPDATA%), сохранение
  shortcut.py   ярлык в меню «Пуск»
  theme.py      режим темы и цвета того, что программа рисует сама
  qt/           интерфейс на Qt (PySide6):
    main_window.py    главное окно, профили, настройки
    bindings_model.py таблица привязок
    binding_dialog.py редактор привязки
    fields.py         поля «ввод с руля» и «клавиша»
    monitor.py        живой монитор руля
    dialogs.py        все вопросы и сообщения пользователю
  app.py        точка входа, лог, защита от второго экземпляра
tests/          property-тесты (hypothesis) и тесты интерфейса (pytest-qt)
docs/           спецификация перехода на Qt
installer/      скрипт Inno Setup
build.ps1       сборка exe, portable и установщика
```

До версии 3.0 интерфейс был на tkinter. Его заменили на Qt: Tk на Windows
заметно тормозил при изменении размера окна, а тёмную тему приходилось
собирать вручную. Подробности — в `docs/2026-09-19-qt-port-design.md`.
